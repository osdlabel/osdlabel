## Drawing tools

osdlabel provides six geometric annotation tools:

<MinimalViewerDemoWrapper />

| Tool               | Shortcut | Geometry                        | Drawing action                                                         |
| ------------------ | -------- | ------------------------------- | ---------------------------------------------------------------------- |
| **Rectangle**      | `r`      | Origin, width, height, rotation | Click and drag to define opposite corners                              |
| **Circle**         | `c`      | Center, radius                  | Click and drag from center outward                                     |
| **Line**           | `l`      | Start point, end point          | Click and drag between endpoints                                       |
| **Point**          | `p`      | Single position                 | Single click to place                                                  |
| **Path**           | `d`      | Array of points, open/closed    | Click to add vertices, double click or `Enter` to finish, `c` to close |
| **Free Hand Path** | `f`      | Array of sampled points         | Click and drag to draw; release to commit                              |

A click without a drag draws nothing with the rectangle, circle or line tool. On release, a shape smaller than 3 screen pixels ([`MIN_SHAPE_SCREEN_PX`](/osdlabel/api/reference/osdlabel/fabric-annotations/variables/min_shape_screen_px/)) is discarded rather than stored, measured as a rectangle's shorter side, a circle's diameter or a line's length. A stray click therefore leaves no invisible annotation behind, and does not count toward a context's `maxCount`. The minimum is in screen pixels, so it is the same at every zoom: to draw a shape smaller than that, zoom in. The point tool is exempt, since a click is how a point is placed.

Paths follow the same rule when they are finished. A path or free-hand stroke whose points all lie within 3 screen pixels of one another is discarded rather than stored, however it was finished: clicks at one spot ended with a double click, `Enter` or `c`, or with a click back on the first point, or a free-hand tap or scribble that never leaves one spot. The tool is then ready to start a new path. A path that reaches 3 pixels in any direction is kept, however small its area: a thin path still paints its outline. As for shapes, the size is judged in the view when the path is finished.

## Drawing workflow

1. Select a drawing tool (toolbar click or keyboard shortcut)
2. The active cell switches to **annotation mode** — OSD navigation is disabled
3. Click/drag on the image to draw the annotation
4. The annotation is created in **image-space** coordinates and stored in the annotation state
5. The `onAnnotationsChange` callback fires with the updated annotation list

## Selecting and editing

Press `v` (or click the select tool) to enter selection mode:

- **Click** an annotation to select it — shows resize handles and rotation control
- **Drag** a selected annotation to move it
- **Drag handles** to resize. What each shape's handles can do keeps it a shape its geometry describes:
  - a **rectangle**'s corner handles keep its proportions, or resize it freely while **Shift** is held; its side handles move one side, with or without Shift;
  - a **circle** has corner handles only, and they always keep it a circle;
  - a **line**, **polyline** or **polygon** has the full set, and **Shift** turns a side handle into a shear, which its stored points follow;
  - a **point** has none: drag it to move it.
- **Drag rotation control** (circle above the annotation) to rotate
- **Escape** deselects the current annotation
- **Delete** / **Backspace** deletes the selected annotation

To edit several annotations together, drag a box from empty canvas over them, or **Shift+click** to add or remove one at a time. A multi-selection can be moved, rotated with its rotation control, and resized from its corners only. It always keeps its proportions, even with Shift held: stretching it would skew a rotated rectangle or turn a circle into an ellipse, which their geometry cannot record. Resizing it moves the point annotations in it apart or together, but each one's dot keeps its size: a point is a position, and its dot is always drawn at its style's radius. The edit saves every annotation in the selection as one change, and the selection stays selected. Only the select tool selects by drag-box, so dragging a drawing tool across existing annotations selects none of them.

## Pan and zoom in annotation mode

While drawing or selecting, you can still navigate:

- **Ctrl/Cmd + drag** — Pan the image
- **Ctrl/Cmd + scroll** — Zoom in/out

These modifier-based gestures pass through to OpenSeaDragon while keeping Fabric in control of regular mouse events.

## Fullscreen

The view controls include a fullscreen toggle that puts the annotator into the browser's native fullscreen mode. Hide it with `showFullscreenControl={false}`, on either `<Annotator>` or `<ViewControls>`. It hides itself where the browser has no element-level Fullscreen API — iPhone Safari, or an `<iframe>` without `allow="fullscreen"`.

### What goes fullscreen

By default, the whole `<Annotator>` — toolbar, filmstrip, grid and status bar together. It claims its own root through `fullscreenTargetRef` on the annotator context.

If you compose those pieces yourself instead of rendering `<Annotator>`, claim your own root the same way:

```tsx
const { fullscreenTargetRef } = useAnnotator();

// Solid
<div ref={(el) => (fullscreenTargetRef.element = el)}>
  <Toolbar />
  <ViewControls />
  <GridView columns={2} rows={1} images={images} />
</div>;
```

In React, wrap the assignment in a `useCallback` so the ref is not detached and reattached on every render:

```tsx
const { fullscreenTargetRef } = useAnnotator();
const setRoot = useCallback(
  (el: HTMLDivElement | null) => {
    fullscreenTargetRef.element = el;
  },
  [fullscreenTargetRef],
);

<div ref={setRoot}>{/* … */}</div>;
```

Or name an element explicitly, which takes precedence over both:

```tsx
<Annotator
  fullscreenTarget={() => document.getElementById('workspace')}
  images={images}
  contexts={contexts}
/>
```

Nothing claimed and no prop set? The toggle falls back to the document element, so it is never inert.

Whatever you target **must contain the annotator's own UI**. Anything rendered outside the fullscreen element is invisible while fullscreen — including the button that exits it, and including tooltips or menus your app portals to `document.body`. Escape and the browser's own affordance still work, and `useFullscreen` still reports the state, so you can render your own exit control if you deliberately target something else.

### Escape does one thing at a time

The browser exits fullscreen on `Escape` and that keypress cannot be intercepted. So while fullscreen, the annotator ignores `Escape` entirely — it will not deselect, clear the active tool, or cancel an in-progress polyline. One press, one effect; press it again once you are out to cancel as usual. Every other shortcut keeps working.

This applies to the Fullscreen API only. Browser-native fullscreen (F11, kiosk mode) is not exited by `Escape` either, so there is nothing to disambiguate and shortcuts behave normally.

### What happens to the view

Entering or leaving fullscreen preserves the centre of the image and scales it by the change in the container's diagonal, so the round trip returns you to the exact zoom and centre you started from. The image is not re-fitted, and annotations stay locked to it throughout.

### Tracking the state yourself

`useFullscreen` is independent of `AnnotatorProvider`, so you can build your own control:

```tsx
const fullscreen = useFullscreen();
const { fullscreenTargetRef } = useAnnotator();

// Solid: accessors. React: plain values.
<button
  onClick={() => {
    const root = fullscreenTargetRef.element;
    if (root) void fullscreen.toggle(root);
  }}
>
  {fullscreen.isFullscreen() ? 'Exit' : 'Fullscreen'}
</button>;
```

`toggle` must be called from within a user gesture — browsers reject a fullscreen request otherwise. It resolves `false` rather than throwing when refused.

### Styling

The `<Annotator>` root paints a dark background so the black fullscreen backdrop does not show through. Override it via `style` if your app is light-themed:

```tsx
<Annotator style={{ background: '#fff' }} images={images} contexts={contexts} />
```

## Polyline tool workflow

The polyline tool is multi-click (not drag-based):

1. Press `d` to activate the polyline tool
2. Click to place each vertex — a preview line follows the cursor
3. Double click, or press `Enter`, to finish as an open polyline
4. Press `c`, or click the first vertex, to close as a polygon
5. Press `Escape` to cancel the polyline in progress

The double click places its own final vertex where you click, so you do not
need a separate click before it.

Polylines require at least 2 points to be committed; polygons require at least 3.

## Free hand path tool workflow

The free hand path tool captures a continuous stroke as you drag:

1. Press `f` to activate the free hand path tool
2. Click and hold, then drag to draw — vertices are sampled automatically as you move
3. **Release** the mouse button to commit the annotation
4. By default the stroke is **closed** (a filled polygon); hold **Shift** while drawing to produce an **open** polyline instead
5. Press `Escape` during a drag to cancel

Closed polygons require at least 3 sampled points; open polylines require at least 2. If the stroke is too short the annotation is discarded automatically.

## Programmatically selecting a tool

Activate a tool through the toolbar UI or keyboard shortcuts. Tools are only available if enabled by the active [annotation context](/osdlabel/guides/annotation-contexts/).

```tsx
const { actions } = useAnnotator();

// Programmatically set the active tool
actions.setActiveTool('rectangle');

// Switch to selection mode
actions.setActiveTool('select');

// Deactivate all tools (navigation mode)
actions.setActiveTool(null);
```
